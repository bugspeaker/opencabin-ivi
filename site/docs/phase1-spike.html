#1단계 기술 검증 (AAOS 에뮬레이터 · VHAL · Appium)

작성 2026-11-13. 목적: 자체 IVI 앱을 만들기 전에, PC 한 대로 차량 신호 주입 → UI 확인 → UI 조작 → 차량 신호 확인 E2E가 되는지 먼저 확인한다.

#결론

확인 항목 결과 근거
Automotive 에뮬레이터 부팅 됨, 약 30초 API 34 android-automotive x86_64, 1024x768
adb root (VHAL 직접 제어용) 됨 이미지가 userdebug
읽기 전용 센서 값 주입 (속도·기어) dumpsys <VHAL> --set cmd car_service inject-vhal-event는 값이 저장되지 않음 (아래 참고)
쓰기 가능 값 (HVAC 온도) cmd car_service set-property-value 앱의 CarPropertyManager와 같은 경로
신호 → UI 됨 HVAC 25.0°C 넣으면 하단 바 77°
UI → 신호 됨 ▼/▲ 1회 = 0.5°C
속도·기어 → 주행 상태 됨 PARKED(0) ↔ MOVING(2), UX 제한 0x1ff, 비최적화 화면에 "You can't use this feature while driving"
Appium(UiAutomator2) 세션 됨, 3초 AAOS 전용 설정 3가지 필요 (아래)
안정성 됨 pytest 3회 연속 5 passed, 1 xfailed, 회당 약 9초

#차량 신호 제어: 명령 3가지의 차이

명령 경로 결과
cmd car_service set-property-value <prop> <area> <값> CarService → VHAL 쓰기 권한 있는 property만. HVAC 성공, 속도는 읽기 전용이라 불가
cmd car_service inject-vhal-event <prop> <area> <값> 이벤트만 발생 저장 값은 그대로라 get-property-value로 확인 불가. 테스트 판정에 쓰지 않는다
dumpsys android.hardware.automotive.vehicle.IVehicle/default --set <prop> -f/-i <값> -a <area> VHAL 직접 (root) 읽기 전용 센서 값도 바뀌고 변경 이벤트가 CarService로 나가서 주행 상태까지 실제로 바뀜
  • VHAL에는 테스트용 --save-prop / --restore-prop가 있다. 픽스처에서 테스트 전후로 값을 저장·복원해서 테스트끼리 영향을 주지 않게 했다.
  • --genfakedata (선형 값 생성, JSON 시나리오 재생)도 있다. 주행 시나리오(가속·감속) 테스트에 쓸 수 있어 3단계 후보로 남긴다.

#Appium을 AAOS에 붙일 때 필요한 것

증상 원인 해결
Neither ANDROID_HOME nor ANDROID_SDK_ROOT environment variable was exported Appium 서버 환경 변수 ANDROID_HOME=C:\android로 서버 실행
Appium Settings app is not running after 30000ms AAOS는 시스템 사용자(0)와 운전자 사용자(10)가 따로 돈다 appium:userProfile = am get-current-user 값, appium:skipDeviceInitialization: true
하단 HVAC 바가 화면 소스에 없음 SystemUI 바는 앱과 다른 창 세션 후 update_settings({"enableMultiWindows": True})

#발견한 결함: 운전석 온도 ▲ 가 홈 버튼에 가려짐

  • 화면: 하단 시스템 바, 1024x768 (automotive_1024p_landscape)
  • 현상: 운전석 온도 ▲ 를 눌러도 온도가 바뀌지 않는다. Appium 클릭, adb shell input tap 모두 같다.
  • 원인: 영역이 겹친다. ▲ [192,682][268,758], 홈 [188,682][264,758]. 72x76px가 겹치고 홈이 위에 있어 탭을 가져간다.
  • 비교: 운전석 ▼, 조수석 ▲·▼ 는 정상 (1회 = 0.5°C).
  • 처리: test_driver_temp_up_is_not_covered_by_home를 xfail(strict=True)로 둔다. 결함이 고쳐지면 XPASS가 되고, strict라서 실패로 바뀌므로 바로 알 수 있다.

#환경에서 막혔던 것

문제 해결
에뮬레이터 35.4.9로 Automotive 이미지 부팅 중 종료 에뮬레이터 37.2.13으로 업데이트
사용자 폴더 경로에 한글 (C:\Users\조예훈\.android\avd) AVD를 C:\android\avd로 옮기고 ANDROID_AVD_HOME 지정
avdmanager가 응답 없음 (cmdline-tools가 SDK XML v4를 못 읽음) AVD config.ini를 직접 작성 (hw.device.name=automotive_1024p_landscape)

#다음 단계로 넘길 것

  • 주행 중 제한 E2E는 기본 앱으로는 판정이 애매하다(어떤 앱이 Distraction Optimized인지 바깥에서 정하기 어려움). 2단계에서 만드는 자체 앱에 DO 화면과 비DO 화면(영상 재생)을 둬서 drive() → 차단 화면 / park() → 복귀를 확인한다.
  • 태블릿(화웨이 DBY-W09, Android 12 기반)은 CarService가 없으므로 앱 안의 Mock 차량 서비스를 adb shell am broadcast로 제어한다. vehicle.py의 Vehicle과 같은 인터페이스로 맞춰 테스트 코드를 그대로 쓴다.

#요구사항

OpenCabin IVI 앱과 Test Bench가 지켜야 할 것을 ID를 붙여 적었습니다. 테스트 코드는 @pytest.mark.req("ID")로 이 ID를 가리키고, ivi-tests/tools/trace_report.py가 둘을 이어 요구사항 추적표를 만듭니다.

출처 열의 '기능'은 이 앱에서 정한 동작이고, '운전자 주의 분산'은 AAOS의 주행 중 UX 제한을, '법규'는 해당 기준을 가져온 것입니다. '모의 환경'은 실제 장비 대신 PC 안에서 흉내 낸 환경에서 확인한다는 뜻입니다.

ID 요구사항 출처
SYS-01 앱은 기기에 맞는 차량 데이터(AAOS는 CarService, 그 밖의 기기는 Mock)에 연결하고, 권한이 없는 신호는 앱이 멈추지 않고 '값 없음'으로 보여 줍니다. 기능
SYS-02 한 기능(음악, 경로 안내, 통화)이 도는 동안 다른 기능(공조, 주행)을 조작해도 앞 기능의 상태는 그대로입니다. 화면 조작과 차량 쪽 변경이 겹쳐도 화면과 차량 신호는 같은 값으로 끝나고, 버튼을 빠르게 눌러도 누른 만큼 바뀝니다. 기능 (동시 조작)
UI-01 화면 틀(아래 바, 분할 화면, 위젯, 알림 센터, 앱 목록, 이전 실행 앱)이 어느 화면에서든 동작합니다. 기능
DRIVE-01 속도와 기어 신호를 주행 정보에 바로 보여 줍니다. 기능
DRIVE-02 P 기어가 아니면(D·N·R로 멈춰 있어도) 영상을 볼 수 없고, P로 바꾸면 멈춘 자리부터 이어서 볼 수 있습니다. 음악은 주행 중에도 쓸 수 있습니다. 운전자 주의 분산
DRIVE-03 주행 중(P가 아니고 속도가 0보다 클 때)에는 글자 입력(내비 검색, 키패드, 어시스턴트 입력)과 일부 차량 제어(사이드 미러 접기, 트렁크)를 막습니다. P가 아닌 채 멈춰 있을 때(신호 대기)는 막지 않습니다. 운전자 주의 분산
HVAC-01 운전석과 조수석 온도는 화면과 차량 신호가 같은 값을 가집니다. 한쪽이 바뀌면 다른 쪽이 따라옵니다. 기능
HVAC-02 온도는 16.0~28.0°C 범위에서 0.5°C 단위로 바뀌고, 끝에 닿으면 그 방향 버튼이 꺼집니다. 차량 쪽에서 범위 밖 값이나 0.5°C 단위가 아닌 값이 와도 앱은 멈추지 않고 그 값을 보여 주며, 범위 밖으로 더 가는 버튼은 꺼집니다. 버튼을 누르면 범위 안의 0.5°C 단위 값으로 맞춰 차량에 씁니다. 기능
HVAC-03 A/C, AUTO, 풍량은 모든 좌석 area에 함께 적용됩니다. 풍량을 직접 바꾸면 AUTO가 풀립니다. 기능
HVAC-04 최대 냉방(FULL)을 켜면 최저 온도와 최대 풍량이 되고, 끄면 켜기 전 값으로 돌아갑니다. 다른 공조 값을 직접 바꾸면 최대 냉방이 풀립니다. 기능
HVAC-05 김서림 제거와 좌석 열선은 누른 유리, 그 좌석에만 적용되고, 화면 여러 곳에 같은 값으로 보입니다. 기능
HVAC-06 SYNC를 켜면 조수석 온도가 운전석을 따르고, 조수석을 직접 바꾸면 SYNC가 풀립니다. 기능
BODY-01 도어 버튼은 모든 문을 함께 잠그고 풀며, 차량 쪽 문 상태를 화면에 보여 줍니다. 기능
ENERGY-01 주행 가능 거리, 배터리, 외기 온도를 화면 단위(km 또는 마일, %, °C)로 보여 줍니다. 기능
ENERGY-02 주행 가능 거리가 30 km 이하면 경고와 충전소 안내를 띄우고 알림 센터에 남깁니다. 충전해서 거리가 늘면 경고를 거둡니다. 기능
CAM-01 기어가 R이 되면 어느 화면에서든 후방 카메라를 띄우고, R에서 벗어나면 보던 화면으로 돌아갑니다. 기능
CAM-02 후방 카메라 화면은 기어를 R로 바꾼 뒤 2.0초 안에 보여야 합니다. FMVSS 111의 2초 기준을 빌렸고, 앱의 카메라 화면 요소가 뜰 때까지를 잽니다(adb 주입과 Appium 조회 시간 포함). 실제 카메라 영상이나 실차에서 잰 값은 아닙니다. 법규 (FMVSS 111 기준)
NAV-01 목적지를 찾아 안내를 시작하고, 남은 거리는 차량 속도 신호를 따라 줄며, 도착하거나 끝내면 안내를 거둡니다. 기능
MEDIA-01 음악, 라디오, 통화는 한 번에 하나만 소리를 냅니다. 통화가 끝나면 듣던 것이 다시 나옵니다. 기능
MEDIA-02 음악과 영상 재생, 라디오 조정과 프리셋, 전화 걸기가 동작합니다. 기능
VOICE-01 음성 명령과 AI 어시스턴트는 말한 사람의 좌석에 맞춰 차량 기능과 앱 기능을 실행합니다. 기능
SET-01 설정과 라디오 프리셋은 앱을 다시 켜도 남고, 초기화하면 기본값으로 돌아갑니다. 속도 단위는 차량 정보 표시에 반영됩니다. 기능
NET-01 차량 네트워크(CAN)로 들어온 주행, 배터리, 도어 신호가 VHAL을 거쳐 화면에 보입니다. 통합 (모의 환경)
NET-02 화면에서 바꾼 공조 값이 CAN 프레임으로 나갑니다. 통합 (모의 환경)
BENCH-01 Test Bench API로 기기, 차량 신호, 실행 결과를 조회하고 신호를 넣을 수 있습니다. 잘못된 값은 거절하고 차량에 넣지 않습니다. 운영
BENCH-02 전원을 껐다 켜도 기기가 정해진 시간 안에 부팅되고, 앱과 공조 기본값이 돌아옵니다. 운영 (모의 환경)
SPIKE-01 AAOS 기본 SystemUI의 공조 바가 VHAL 신호와 이어지고, 속도와 기어가 주행 상태를 바꿉니다. 기술 검증 (1단계)

DRIVE-02와 DRIVE-03의 '주행 중'은 AAOS의 UX 제한(CarUxRestrictions) 표를 따릅니다. P는 제한이 없고, P가 아닌 채 멈춰 있으면(속도 0) 영상만 막고(NO_VIDEO), 속도가 0보다 크면 모두 막습니다(0xff). 앱은 기어와 속도가 아니라 플랫폼이 알려 준 제한 종류를 보고 기능을 막고, 태블릿의 Mock 차량은 같은 표로 제한을 계산합니다. AOSP 문서가 앱에 권하는 방식이고, 표는 2026-11-23 AAOS 에뮬레이터의 설정(dumpsys car_service --services CarUxRestrictionsManagerService)에서 확인했습니다. 그전에는 AAOS 앱이 D 기어로 멈춰 있을 때 검색까지 막고, 태블릿은 영상을 막지 않았습니다(3장 13번, #47).

#복합 요구사항: 조건마다 확인하는 곳

요구사항 하나에 조건이 여럿이면, 테스트 이름이 붙어 있다는 것만으로 모든 조건을 확인했다고 할 수 없습니다. 추적표의 '요구사항 ID 연결 누락 0'은 연결이 빠지지 않았다는 뜻이고, 조건별 검증이 충분하다거나 표준을 지켰다는 뜻은 아닙니다. 그래서 조건을 나누고, 조건마다 어느 테스트의 어떤 확인(assert 또는 대기)이 그 조건을 보는지 적었습니다. 확인하지 않는 조건은 '확인하지 않음'으로 남겼습니다.

trace_report.py가 이 표의 테스트가 실제로 있고 그 요구사항 ID를 달고 있는지 검사합니다. 테스트 이름이 바뀌거나 요구사항 표시가 빠지면 CI의 unit job이 실패합니다.

조건 내용 테스트 그 조건을 보는 확인
SYS-01.1 기기에 맞는 차량 데이터에 연결합니다 (AAOS는 CarService, 태블릿은 Mock) test_app_starts_with_vehicle_source_for_device assert app.source_badge() == device.vehicle.badge, 연결 안 됨·오류 표시가 없습니다
SYS-01.2 연결한 차량 값이 시작 화면에 맞게 보입니다 test_parked_on_start wait_text("speed_value", "0"), assert home.gear() == "P"
SYS-01.3 권한이 있으면 공조를 제어할 수 있습니다 test_hvac_is_controllable assert not climate.unavailable() 뒤 화면 + 한 번이 차량 22.5°C로
SYS-01.4 권한이 없는 신호는 앱이 멈추지 않고 '값 없음'으로 보여 줍니다 test_signal_without_permission_shows_no_value AAOS에서 pm revoke로 CAR_ENERGY를 뺀 뒤 앱을 새로 띄우고 wait_visible("range_unavailable"), 거리·배터리 표시가 없는지 봅니다. 권한이 있는 외기 온도(18.0°C)와 속도(50)는 그대로 보이고, 거리 12 km를 넣어도 경고와 충전소 카드가 뜨지 않는지 stays로 봅니다. 태블릿의 Mock 차량에는 권한이 없어 AAOS에서만 확인합니다
SYS-02.1 음악을 틀어 둔 채 공조(두 좌석 온도, 풍량, A/C)를 바꾸면 값은 모두 차량에 들어가고, 음악은 같은 곡으로 재생 중입니다 test_music_keeps_playing_while_climate_is_operated 차량 wait_value 22.5·21.5°C, wait_signal 풍량 4·A/C 꺼짐, 음악 화면 wait_text("now_playing_title", title)와 wait_text("playback_state", "재생 중")
SYS-02.2 음악 화면을 보는 동안 차량 쪽 온도가 바뀌어도 재생은 그대로입니다 test_music_keeps_playing_while_climate_is_operated car.set_temperature(Seat.DRIVER, 24.0) 뒤 아래 바 wait_temperature(24.0), 1.5초 동안 stays(재생 중이고 같은 곡)
SYS-02.3 경로 안내와 음악 중에 달리며 아래 바로 온도를 바꾸면, 온도는 차량에 들어가고 안내는 같은 목적지로 계속 줄고 음악은 재생 중입니다 test_guidance_and_music_continue_while_temperature_changes_on_the_move 120 km/h에서 차량 wait_value 22.5·21.5°C, 주행 정보 경로가 '회사'로 시작하고 8.5 km 이하로 wait_until, 음악 wait_text, 내비 destination() == "회사"
SYS-02.4 통화 중에 공조를 바꾸면 차량에 들어가고 통화는 이어지며, 끝나면 듣던 곡이 다시 나오고 공조 값은 그대로입니다 test_climate_works_during_call_and_music_resumes_after 차량 wait_value 22.5°C와 풍량 4, 음악 '통화 중', 통화 시간이 늘어나는지 wait_until, 끊은 뒤 '재생 중'과 같은 곡, assert car.temperature(Seat.DRIVER) == 22.5
SYS-02.5 화면 조작과 차량 쪽 변경이 겹쳐도 화면과 차량 신호가 같은 값으로 끝나고, 다른 좌석은 그대로입니다 test_screen_and_vehicle_changes_at_once_end_in_same_value 다른 스레드가 차량 쪽에 25.0·24.0·26.0°C를 쓰는 동안 + 세 번, wait_until(화면 == 차량)과 1.5초 stays, 범위와 0.5°C 단위, 조수석 22.0°C
SYS-02.6 버튼을 빠르게(누름 사이 0.1초) 네 번 누르면 네 번 모두 차량에 들어갑니다 test_quick_taps_are_all_applied adb 셸 한 번에 input tap 네 번, 차량 wait_value(24.0), 화면 wait_temperature(24.0), 1.5초 stays. 좌석 2
HVAC-02.1 버튼 한 번에 0.5°C 바뀝니다 test_button_changes_signal_by_one_step 차량 값 wait_value(car.temperature(seat), 22.5)(▼는 21.5)와 화면 wait_temperature를 따로 봅니다. 좌석 2 × 방향 2
HVAC-02.2 끝값(16.0, 28.0°C)에서는 그 방향 버튼이 꺼지고 반대쪽은 눌립니다 test_buttons_disabled_at_limits wait_enabled("<좌석>_temp_down", False)와 assert climate.can_increase(seat). 28.0°C는 반대

HVAC-02.4 차량 쪽 범위 밖 값(15.5, 28.5°C)을 화면에 보여 주고, 범위 밖으로 더 가는 버튼은 꺼집니다 test_out_of_range_signal_is_shown_safely wait_temperature(seat, 15.5), wait_enabled("driver_temp_down", False). 15.5°C를 그대로 보여 주는 것은 AAOS에서만 확인합니다(태블릿 Mock은 16.0°C로 자릅니다)
HVAC-02.5 범위 밖 값에서 버튼을 누르면 범위 안의 값을 차량에 씁니다 test_out_of_range_signal_is_shown_safely ▲ 뒤 wait_value(car.temperature(seat), 16.0)(AAOS), 16.5(태블릿)

HVAC-02.7 이상한 값이 와도 앱이 멈추지 않습니다 test_out_of_range_signal_is_shown_safely, test_off_grid_signal_steps_back_to_grid 값이 화면에 보이고 그 뒤 버튼이 동작하는지 봅니다. 테스트 도중 이 앱의 크래시(FATAL EXCEPTION, Fatal signal)나 ANR이 logcat에 남으면 화면 판정이 통과해도 그 테스트를 실패로 합니다(모든 E2E 공통, ivi/crashes.py)
HVAC-04.1 FULL을 켜면 전 좌석 최대 냉방, 최저 온도, 최대 풍량이 됩니다 test_max_ac_sets_signal_and_coldest_settings wait_until(all(car.signal_all(Signal.MAX_AC))), wait_signal(car, Signal.FAN, 7), 좌석마다 wait_value(car.temperature(seat), 16.0)

HVAC-04.6 차량 쪽에서 바뀐 최대 냉방이 화면 토글에 보입니다 test_max_ac_signal_is_shown_on_toggle wait_checked("max_ac", True), 끄면 False

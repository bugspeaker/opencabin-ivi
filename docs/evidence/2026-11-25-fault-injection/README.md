## 놓친 결함 F08

### 왜 놓쳤나

`test_seat_heat_signal_is_shown_everywhere`는 열선 신호를 바꾼 뒤 공조 화면과 아래 바를 보고, 마지막에 빠른 제어 화면을 새로 열어 '1단'을 확인했습니다. `remember { }`는 화면을 처음 그릴 때 값을 붙잡기 때문에, 신호를 바꾼 뒤 화면을 새로 열면 맞는 글자가 보입니다. 빠른 제어 열선에는 화면을 열어 둔 채 신호가 바뀌는 경우와 타일을 누르는 경우를 보는 테스트가 없었습니다. 공조 화면과 아래 바는 화면을 열어 둔 채 바꾸는 경우를 이미 보고 있었습니다.

### 보강

같은 테스트 끝에 두 단계를 더했습니다([test_vehicle_signals.py](../../../ivi-tests/tests/test_vehicle_signals.py)의 `test_seat_heat_signal_is_shown_everywhere`). 새 테스트를 만들지 않고 기존 테스트를 보강해서 테스트 수는 150개 그대로입니다.

1. 빠른 제어를 열어 둔 채 차량 쪽에서 열선을 2단으로 바꾸고, 글자가 '2단'이 되는지 봅니다.
2. 빠른 제어의 열선 타일을 누르고, 차량 신호와 글자가 다음 단계인 '1단'이 되는지 봅니다.

## 방법

- **기준.** 기준 커밋 `574d5df`의 앱 코드는 0.4.2(`de9d062`)와 같고, E2E 코드는 헤드라인 실행 `101de99`와 같습니다. 대조군 F00은 버전 이름만 `0.4.2-fi.F00`으로 바꾼 빌드입니다.
- **에뮬레이터.** 결함 APK를 설치하고 테스트 150개를 모두 돌렸습니다. 명령은 헤드라인 실행과 같은 `pytest --reruns 1`이고, 화면 저장(`--shots`)만 뺐습니다. 결함 하나에 13분쯤 걸렸습니다.
- **태블릿.** 화웨이는 adb 설치마다 기기 화면에서 승인해야 합니다. 그래서 결함과 관련된 테스트 파일만 돌려 승인 사이 시간을 줄였습니다(결함마다 4~60개). 대조군은 이미 설치돼 있던 main 0.4.2로 150개를 모두 돌렸습니다. 대조군 빌드 F00을 따로 설치하지 않은 것은 승인을 하나 줄이기 위해서입니다. F00과 main 0.4.2는 버전 이름만 다릅니다.
- **판정.** 재시도 뒤에도 실패한 테스트가 하나 이상 있고 그 테스트가 같은 기기의 대조군에서 통과했으면 '탐지'로 셉니다. 재시도로 통과한 것(flaky)만 있으면 탐지로 세지 않습니다. 설치된 APK의 버전 이름에 그 결함의 id가 없으면 그 실행은 세지 않습니다. 판정은 [`tools/fault_report.py`](../../../ivi-tests/tools/fault_report.py)가 결과 파일에서 다시 셉니다.

## 진행 중에 있었던 일

- **첫 시도 중단.** 11-24 22시 20분에 시작한 첫 시도는 대조군이 30%쯤 돌았을 때 PC를 꺼서 멈췄습니다. 같은 시간에 결함 APK 10개를 빌드하고 태블릿 대조군도 돌려 평소보다 많이 느렸습니다. 결과 파일이 만들어지지 않아 남기지 않았고, 11-25 아침에 처음부터 다시 돌렸습니다. 태블릿 대조군(`fi-F00-mock`)은 그 전에 끝난 것을 그대로 썼습니다.
- **태블릿 설치 승인.** F02(1번)와 F04(3번)의 설치가 `INSTALL_FAILED_ABORTED: User rejected permissions`로 끝났습니다. 확인 창을 45초쯤 안에 누르지 않으면 거절로 처리됩니다. 처음 F02 실패 때는 스크립트가 다시 시도하지 않고 F03으로 넘어가서, F03이 순서보다 먼저 한 번 설치됐습니다. 스크립트를 고친 뒤 F02부터 순서대로 다시 했습니다. F05부터는 사용자가 태블릿 개발자 옵션의 ADB 설치 확인을 꺼서 승인 없이 설치했고, 건너뛴 F04는 끝에 다시 넣었습니다.
- **F01 실행의 흔들림 1건.** `test_signal_is_shown_on_climate_and_home[passenger]`가 adb 서버 연결이 잠깐 끊겨(`cannot connect to daemon at tcp:5037`) 실패하고 재시도에서 통과했습니다. 같은 시간에 태블릿 쪽 adb 명령(설치 시도, 상태 확인)을 여러 번 멈추고 다시 띄웠지만, 끊긴 원인은 확인하지 못했습니다. 결함과 상관없는 테스트라 탐지로 세지 않았습니다.
- **에뮬레이터 재부팅.** 실행마다 마지막 테스트(`test_power`)가 에뮬레이터를 껐다 켭니다. 원래 동작입니다.
